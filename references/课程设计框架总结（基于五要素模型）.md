# 📚 课程设计框架总结（基于五要素模型）

本文件是辅助模板，执行范围与顺序以现行 [SKILL.md](../SKILL.md) 为准。数量、比例、覆盖率、周期和服务成本均须结合课型、学员、已售承诺及可用资源决定；下文示例不是已验证的通用数据，也不能替代实际试教。

## 🎯 设计流程概览

```
课程五要素（起点-终点-交付-服务-时间）
    ↓
比较并确认课程组织路线（已定或明确授权代选时不重复确认）
    ↓
阶段、单元与逐课框架（起点→终点→验证→容量判断）
    ↓
一级知识点（强弱交付分级）
    ↓
交付标准 + 服务体系 + 作业体系
    ↓
数据埋点（验证目标达成）
```

---

## 📐 Step 1：课程五要素设计

### 1.1 起点分析
- 目标学员画像（年龄/职业/经验水平）
- 能力现状（具体可量化）
- 典型困惑（用"为什么不会..."句式描述）

### 1.2 终点设定
- 价值及能力目标（数量依课程规模与实际需要确定）
- 验证标准（可测量的标准）
- 终点与起点的差距判断

### 1.3 交付体系
- 列出目标所需知识点（数量依实际规模确定）
- 强弱交付分级：
  - **强交付**：课程重点达成，配置适用的学习、验证及反馈
  - **弱交付**：按目标了解即可
- 比例与强交付点数量依课型、课时及学员负荷决定，不套固定70/30或固定数量

### 1.4 服务体系
- 基于课型、实际承诺和资源选择服务级别及反馈方式，不预设逐人服务。
- 为每个强交付点配置适合的学习或理解验证，可共享反馈机制；无作业或无人工服务按实际条件设计。

### 1.5 时间体系
- 总学习周期（1周/2周/1个月）
- 每个模块学习时长
- 学员时间投入能力判断

## 📊 Step 2：阶段拆分

### 2.1 拆分原则
依现行 Skill 先比较适用的课程组织路线及其成果、负荷和资源条件；确认路线或取得明确代选授权后，再确定阶段进阶和阶段内单元。技能递进、作品/项目单元及场景任务可按学科组合，不固定一种路线。

### 2.2 阶段数量建议
- 依课程目标、时长与学习进阶决定，不由固定天数直接套阶段数量。
- 阶段内可按技能、作品、项目或场景组织单元；避免拆得过碎或负荷过重。

### 2.3 阶段输出格式
```markdown
## 第X阶段：XX期（Day X-X）
**阶段起点与先修：** [已知和计划学过的能力、未知项]
**阶段终点与成果：** [具体状态、能力或产出]
**知识点与对应单元：** [强弱交付、关键下位内容及相关课次]
**交付标准与阶段验证：** [观察什么、用什么证据、何时由谁或自查]
**练习与反馈：** [进阶关系、适用策略及真实资源条件]
```

## 📚 Step 3：一级知识点拆解

### 3.1 知识点拆解框架

```markdown
## 一级知识点：[知识点名称]

### 交付标准（怎么算交付）
学员能够：
- [按实际目标列出具体能力描述]

**验证方式：** [如何验证学员真的掌握了]

### 服务体系设计（How）
- **[适用的服务策略]**：[做法、对象、时机与资源条件]

### 作业体系设计（How）
**作业进阶路径：**
- [适用的练习/作业]：[形式、递进关系] → [反馈机制]

**配套资源：**
- [必做材料清单]
- [选做材料清单]
```

### 3.2 服务体系常用策略（6种）

| 策略 | 适用场景 | 示例 |
|------|---------|------|
| **引导式互动** | 破冰期，建立参与感 | 开营破冰、直播演示、社群排行榜 |
| **案例驱动** | 技能学习期，降低理解门槛 | 好坏对比、完整拆解、优秀学员分享 |
| **工具赋能** | 整合期，降低操作难度 | 提供模板、直播演示、1v1答疑 |
| **项目式学习** | 以项目或作品组织学习，适用时可贯穿课程 | 单元成果、过程反馈、综合项目 |
| **同伴激励** | 全程，激发持续动力 | 小组互评、社群投票、优秀案例展示 |
| **仪式感营造** | 评选期，强化成就感 | 榜单公布、毕业典礼、专属福利 |

### 3.3 作业体系反馈机制（4层）

| 反馈层级 | 使用前提 | 适用场景 |
|---------|---------|---------|
| **自查清单** | 学员能获得示范和检查标准 | 适合独立检查的任务 |
| **助教点评典型案例** | 有助教和经同意的案例 | 讨论共性问题 |
| **小组互评** | 有合适的组织方式与评价支持 | 需要同伴视角的任务 |
| **人工1v1反馈** | 人员、人数、反馈频次及时间可承载 | 已配置的针对性反馈 |

### 3.4 作业难度梯度设计

| 阶段 | 难度策略 | 理由 |
|------|---------|------|
| **基础期** | 降低门槛 | 建立信心，避免早期流失 |
| **进阶期** | 保持稳定 | 巩固技能，形成习惯 |
| **整合期** | 提供梯子 | 降低整合难度，避免卡壳 |
| **应用期** | 结合实际任务 | 依课程目标验证迁移或成果 |

### 4.2 数据使用边界
- 到课率、提交率和成果表现须按实际项目采集与口径分析；没有数据时不假设固定衰减或优秀率。
- 选择与课程目标及服务可承载条件相关的指标，主观体验与可观察能力分别记录。

## 🎯 设计原则总结

### 核心原则（5条）
1. **问题驱动**：一切设计回归"解决谁的什么问题"
2. **类型先行**：先确定课程类型，再匹配服务强度
3. **交付分级**：强弱交付必须区分，避免平均用力
4. **服务适配**：服务设计要与课程类型和交付目标匹配
5. **节奏可控**：时间体系要考虑学员消化能力和服务承载力

### 质量检查清单
**起点终点：**
- [ ] 学员画像具体可感知？
- [ ] 终点目标可验证？
- [ ] 起点到终点的跨度合理？

**交付体系：**
- [ ] 强交付点数量与学员、课时及服务承载相符？
- [ ] 每个强交付点有与课型匹配的学习方式与理解或能力验证？
- [ ] 弱交付内容的范围和深度是否足以支撑目标，是否存在可精简之处？

**服务体系：**
- [ ] 服务级别与课程类型匹配？
- [ ] 每个强交付点有反馈机制？
- [ ] 学员知道何时得到反馈？

**时间体系：**
- [ ] 总学习周期符合学员时间投入能力？
- [ ] 预留了消化时间？
- [ ] 节奏点明确？

**整体：**
- [ ] 五要素相互支撑？
- [ ] 能用一句话说清楚课程价值？

## 💼 实际应用建议

### 调用方式
```
我想设计一门[主题]课程，目标学员是[描述]，预计时长[X天]。

请按照课程设计框架帮我：
1. 完成五要素设计（起点/终点/交付/服务/时间）
2. 拆分阶段并明确阶段目标
3. 拆解一级知识点（交付标准+服务体系+作业体系）
4. 设计数据埋点
```

### 迭代优化路径
1. **初稿**：完成五要素及所需路线选择，再进行阶段拆分
2. **细化**：逐个拆解一级知识点
3. **验证**：用适合的学习证据和可获得的运营数据检查可行性
4. **调整**：根据风险点优化设计
