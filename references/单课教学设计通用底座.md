# 单课教学设计通用底座

## 什么时候用、输入是什么

作为[扩展索引](单课设计扩展索引.md)之后的下游方法，仅对已经获准设计的一节课使用。输入优先取已定框架：本课在系列里的作用、学员真实或预计起点、可观察终点、核心内容、时长、交付形式、师资/反馈能力、已有材料和限制。未知项分成事实、建议假设和待核；前一课教过不等于学员已掌握。独立单课先用同一套字段写出简短课框架，不强行生成阶段表。

只有主题或用户不懂如何提供信息时，先用日常语言提出一个可能的学员、学习场景和期待变化；用户允许交互时，在答复前部给 1—3 个最影响设计的具体问题或带理由的选项；用户不清楚时可选“按你的建议”，不要要求其先懂课型、框架或教学术语。用户已授权完整设计且未要求先确认时，可在前置选项后继续给标明假设的方案，不把提问本身当成额外停工门槛。完整系列课仍依主 Skill 比较路线并等待选择，除非已指定路线、明确授权代选或要求一次完成。独立单课不需要先确定系列课的组织路线；用户明确要求不再提问、直接产出、授权代选或无法提供更多信息时，不再追问，以合理假设继续，确实无法安全或履约的部分标缺口。

## 把一节课从目标设计到证据

1. **锁定本课终点。** 写学员在什么材料或情境下能判断、解释或完成什么，说明一个最重要的学习困难；同时保留用户真正想获得的体验或价值。目标多到本课装不下时，指出取舍和后续补学，不假装全部覆盖。
2. **先想如何看到变化。** 为每项核心目标设计一个可观察的例子、回答、操作或作品，以及判断要点；理解课可以比较和解释，技能课需要看操作或结果。答案复述不自动证明迁移；反馈条件不足时写成可自查或抽样观察，不冒称逐人纠正。
3. **设计到达终点所需的内容。** 选必要的概念、判断规则、材料或步骤；安排一个能看到推理/操作的示范，一个让学员自己做的机会，及针对典型错误的反馈或自查。纯认知欣赏类可用比较、提问或自我反思替代强制实操作业；要说明如何发现理解情况。每个内容块须服务目标，不能只排“讲解、练习”。
4. **按条件组织环节。** 明确学员和讲者在每一环节做什么、用什么具体材料、形成什么回答或产出、如何接到下一步。给出的时长是设计估计，合计要等于可用时长并留出必要缓冲；不同步/录播可用暂停提示、示例答案与自查表，不能假设实时点名。现场可见范围、人数、师资不足时改变反馈方式。
5. **检查证据链。** 对照“目标 → 示范/内容 → 学员动作 → 判断依据 → 反馈/调整”，逐项发现缺环；有多项核心目标时逐项覆盖。判断活动能否在时长、材料与人员条件下执行，标出需要教师审核、试讲或真实学员验证的部分。设计估算不是试教结果。

## 交付给用户

给出可直接备课的方案：本课定位和事实/假设；目标及判断标准；带时间的环节表（环节、讲者动作与材料、学员动作、反馈/转场）；至少一个具体示范或示范提纲，以及与目标匹配的练习题、参考判断与可执行反馈；最后说明材料/师资缺口和试教观察点。用户只要结构时可压缩；用户要求逐字稿或课件时在下游另按其明确范围展开。虚构练习要明示，不能伪造用户业务事实。

## 依据与限制

上述方法是本项目的**设计建议**，其中目标、教学活动和评估相互对齐借鉴 Carnegie Mellon Eberly Center 的[学习目标](https://www.cmu.edu/teaching/designteach/design/learningobjectives.html)与[评估选择](https://www.cmu.edu/teaching/designteach/design/assessments.html)。这不是作者专属框架，不证明某次课程已经有效；学科事实、具体示范和真实教学效果需另核。更多来源见[证据状态](单课设计来源与证据状态.md)。
